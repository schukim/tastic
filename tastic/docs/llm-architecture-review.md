# LLM 아키텍처 검토

## 현재 구조

### Edge Functions (5개)

각 기능마다 독립된 Edge Function이 있고, 모두 **OpenAI GPT-4o**를 사용한다.
(CLAUDE.md에는 Claude라고 명시되어 있으나 실제 코드는 OpenAI API)

| Function | 역할 | temperature | 비고 |
|---|---|---|---|
| `verify-content` | 작품 존재 여부 확인, 후보 반환 | 0.1 | 사실 기반, 창의성 최소 |
| `generate-question` | 인터뷰 질문 생성 (최대 6턴) | 0.7 | 자연스러운 대화체 |
| `generate-review` | 인터뷰 대화 → 1인칭 평론 변환 | 0.4 | 창의적이되 일관성 유지 |
| `analyze-taste` | 누적 평론 기반 취향 분석 | 0.2 | 근거 기반, 추측 최소 |
| `recommend-content` | 취향 기반 콘텐츠 추천 | 0.5 | 크로스 카테고리 |

### 인터뷰 세션 메모리 구조

LLM은 대화를 자체적으로 기억하지 않는다. 앱이 매 호출마다 컨텍스트를 직접 조립해서 전달하는 방식.

`generate-question` 호출 시 전달되는 데이터:

```
content: {
  title, category, creator, year, genre, metadata
}
conversation_history: [
  { role: "interviewer", text: "..." },
  { role: "user",        text: "..." },
  ...  // 처음부터 끝까지 누적
]
question_count: N
language: "ko" | "en"
```

호출할 때마다 대화 전체가 다시 전송된다.

## 현재 한계

### 웹 서칭 없음

LLM은 학습 데이터에 있는 지식만 사용한다. 웹 검색은 Tool Use 기능으로 명시적으로 붙여야 하는데 현재 코드에는 없다.

- Claude.ai 웹앱, ChatGPT 앱 → 검색 기능 내장
- API 호출 → 명시적으로 search tool 추가해야 검색 가능

GPT-4o 학습 데이터 컷오프는 2024년 초. 이후 출시 작품이나 국내 소규모 전시/공연은 모르거나 부정확할 수 있다.

### `verify-content`도 동일한 한계

작품 검증도 GPT-4o 학습 데이터 기반이라 실제 DB 검색이 아니다.

## 개선 방향 검토

### DB API vs 웹 서칭

| 방식 | 장점 | 단점 |
|---|---|---|
| DB API | 빠름, 정확, 무료, 구조화된 데이터 | 카테고리별 API 다름, 줄거리 없는 경우 있음 |
| 웹 서칭 | 모든 카테고리 커버, 최신 작품 가능 | 불안정, 느림, 세션당 ~$0.03 추가 |

### 카테고리별 DB API 현실

| 카테고리 | API | 줄거리 포함 |
|---|---|---|
| 영화 | TMDB (무료) | ✅ |
| 책 | Google Books API (무료) | ✅ |
| 음악 | Spotify API (무료) | ❌ (가사/설명 없음) |
| 미술 | Met Museum API 등 (무료) | ❌ (해설 없음) |
| 전시/공연 | 국내 공개 API 없음 | ❌ |

미술/전시/공연은 DB API로 커버 불가 → 웹 서칭이 유일한 방법.
결과적으로 **모든 카테고리를 웹 서칭으로 통일**하는 게 일관성 있는 구조.

### 비용

| 방식 | 세션당 비용 |
|---|---|
| 현재 (학습 데이터만) | ~$0.01 |
| 웹 서칭 1회 추가 | ~$0.04 |

### 제안 아키텍처

```
유저: 작품 제목 + 창작자 입력
        ↓
verify-content: 작품 확인 (DB API 또는 현재 방식)
        ↓
웹 서칭 1회: 줄거리, 주요 등장인물/요소, 핵심 장면 수집
        ↓
generate-question: 작품 세부 정보 포함하여 인터뷰 진행 ✅
        ↓
generate-review: 인터뷰 대화만 사용 (세부 정보 미전달) ✅
```

**`generate-review`에 작품 세부 정보를 넣지 않는 이유:**
평론 원칙상 "사용자가 실제로 언급한 내용만 포함"이기 때문에, 작품 정보를 추가하면 LLM이 유저가 말하지 않은 내용을 평론에 끼워넣을 위험이 있다. 평론 품질은 인터뷰 대화의 풍부함에 달려 있고, 인터뷰 질문이 좋아지면 평론도 자연히 좋아진다.
