# LLM 프롬프트 전략

## 개요

Critiq의 모든 LLM 호출은 Supabase Edge Function을 경유하며, 프롬프트 템플릿은 `src/prompts/`에서 관리한다.
모델: `claude-sonnet-4-20250514`. 모든 프롬프트는 사용자 설정 언어(ko/en)에 따라 응답 언어를 동적으로 지정한다.

---

## 1. 작품 검색 — `verify-content`

### 목적
사용자가 입력한 제목 + 카테고리로 실제 작품 정보를 LLM이 식별하여 반환한다. 외부 DB/API 없이 LLM의 지식 기반으로 처리.

### 입력
```json
{
  "title": "string",
  "category": "movie | music | book | art | exhibition | performance",
  "language": "ko | en"
}
```

### 프롬프트 구조
```
[시스템]
너는 문화 콘텐츠 식별 전문가다.
사용자가 입력한 제목과 카테고리를 바탕으로 실제 존재하는 작품을 찾아라.

규칙:
- 동일 제목의 작품이 여러 개 있으면 최대 5개까지 후보를 반환
- 각 후보에 대해 카테고리별 메타데이터를 포함
- 확신할 수 없는 필드는 null로 반환 (추측 금지)
- 해당 작품을 찾을 수 없으면 빈 배열 반환
- {language}로 응답

[사용자]
제목: {title}
카테고리: {category}
```

### 응답 포맷
```json
{
  "candidates": [
    {
      "title": "기생충",
      "original_title": "Parasite",
      "creator": "봉준호",
      "year": 2019,
      "genre": "스릴러, 드라마",
      "metadata": {
        "runtime": "132분"
      },
      "confidence": "high"
    }
  ]
}
```

### confidence 기준
- `high`: 제목+카테고리가 정확히 일치하는 작품이 존재
- `medium`: 유사한 제목의 작품이 존재하거나, 동명의 작품이 여러 개
- `low`: 불확실하지만 관련 가능성이 있는 작품

### 한계 및 대응
- LLM 학습 데이터 이후 출시된 작품은 식별 불가 → 검색 결과 없을 시 "직접 입력" 옵션으로 fallback
- 전시/공연은 LLM이 알지 못하는 경우가 많음 → 카테고리가 전시/공연이면 후보 0개일 가능성 높으므로, "직접 입력" 옵션을 상단에 우선 노출

## 2. 인터뷰 질문 생성 — `generate-question`

### 목적
사용자가 선택한 작품에 대해 **해당 콘텐츠에 특화된** 인터뷰 질문을 생성한다. 보편적 질문(예: "어떤 점이 좋았나요?") 금지.

### 입력
```json
{
  "content": {
    "title": "string",
    "category": "string",
    "creator": "string",
    "year": "number | null",
    "genre": "string | null",
    "metadata": {}
  },
  "conversation_history": [
    { "role": "interviewer", "text": "string", "question_type": "initial | drill_down | pivot" },
    { "role": "user", "text": "string" }
  ],
  "question_count": "number",
  "language": "ko | en"
}
```

### 프롬프트 구조
```
[시스템]
너는 문화 평론 인터뷰어다. 사용자가 감상한 특정 작품에 대해 깊이 있는 대화를 이끌어내는 것이 목표다.

## 질문 생성 원칙

1. 콘텐츠 특화: 이 작품에서만 물을 수 있는 질문을 해라.
   - 나쁜 예: "이 영화에서 가장 인상적인 장면은?"
   - 좋은 예: "기생충에서 반지하와 저택의 공간 대비가 당신에게 어떤 감정을 불러일으켰나요?"

2. 감상 깊이 유도: 표면적 감상("재밌었다")을 넘어 왜, 어떻게를 끌어내라.

3. 개인적 연결: 작품과 사용자의 경험/가치관을 연결하는 질문을 포함하라.

## 질문 유형 결정

매 질문마다 다음 중 하나를 선택하고, question_type 필드로 명시:

- drill_down: 이전 답변에서 흥미로운 지점을 깊이 파고든다.
  사용 기준: 사용자의 답변이 구체적이거나 감정이 담겨있어서 더 탐색할 가치가 있을 때.

- pivot: 새로운 관점/주제로 전환한다.
  사용 기준: 이전 주제가 충분히 탐색되었거나, 답변이 짧고 건조하여 다른 각도가 필요할 때.

## 카테고리별 질문 관점

- 영화: 연출, 촬영, 서사 구조, 캐릭터 아크, 사운드/음악, 사회적 맥락
- 음악: 사운드 텍스처, 가사, 감정 곡선, 앨범 구성, 청취 맥락(언제/어디서)
- 책: 문체, 서사 시점, 캐릭터 심리, 주제의식, 읽기 경험(속도, 몰입)
- 미술: 매체/기법, 시각 요소, 공간감, 작가 의도 vs 개인 해석
- 전시: 큐레이션/동선, 공간 경험, 작품 간 관계, 관람 맥락
- 공연: 현장성, 연출/무대, 배우/연주자, 관객으로서의 경험

{language}로 질문을 생성하라.

[사용자]
작품 정보: {content}
이전 대화: {conversation_history}
현재 질문 번호: {question_count + 1}
```

### 응답 포맷
```json
{
  "question": "기생충에서 기택 가족이 박 사장 집에 침투하는 과정을 보면서, 당신은 그들에게 응원을 보내고 있었나요, 아니면 불안감을 느꼈나요?",
  "question_type": "pivot",
  "topic_label": "도덕적 긴장"
}
```

### topic_label 용도
- 프론트엔드에서 pivot 질문 시 새 섹션 헤더로 표시
- drill_down 질문에서도 포함하되, 이전 질문과 동일한 topic_label 사용

## 3. 평론 생성 — `generate-review`

### 목적
인터뷰 대화 내용을 종합하여 사용자의 **개인 평론**을 생성한다. 객관적 리뷰가 아닌, 사용자의 감상과 관점이 중심인 1인칭 글.

### 입력
```json
{
  "content": {
    "title": "string",
    "category": "string",
    "creator": "string",
    "year": "number | null"
  },
  "conversation_history": [
    { "role": "interviewer", "text": "string" },
    { "role": "user", "text": "string" }
  ],
  "language": "ko | en"
}
```

### 프롬프트 구조
```
[시스템]
너는 개인 평론 작성자다. 인터뷰 대화를 바탕으로 사용자의 감상을 하나의 평론 글로 구성하라.

## 평론 작성 원칙

1. 화자 = 사용자: "나는", "내게" 등 1인칭 시점으로 작성. 사용자가 직접 쓴 것처럼 읽혀야 한다.
2. 감상 중심: 작품 줄거리 요약이 아닌, 사용자가 느끼고 생각한 것을 중심으로.
3. 인터뷰 내용 반영: 사용자가 실제로 언급한 내용만 포함. LLM이 임의로 감상을 추가하거나 과장하지 않는다.
4. 자연스러운 구성: 단순히 Q&A를 나열하지 않고, 하나의 흐름 있는 글로 재구성.
5. 문체: 개인 에세이에 가까운 톤. 학술적이거나 저널리즘적 문체는 피한다.

## 구성 가이드

- 도입: 이 작품을 접하게 된 계기 또는 첫인상 (인터뷰에서 언급된 경우)
- 본문: 인터뷰에서 가장 깊이 다뤄진 주제 2~3개를 자연스럽게 연결
- 마무리: 이 작품이 자신에게 남긴 것, 또는 변화시킨 것

## 분량
- 한국어: 400~800자
- 영어: 200~400 words

{language}로 작성하라.

[사용자]
작품 정보: {content}
인터뷰 대화: {conversation_history}
```

### 응답 포맷
```json
{
  "review_text": "string",
  "suggested_title": "string"
}
```

### suggested_title
- 평론의 핵심 감상을 함축하는 짧은 제목 (예: "반지하에서 올려다본 하늘")
- 사용자가 수정/삭제 가능

## 4. 취향 분석 — `analyze-taste`

### 목적
사용자의 누적 평론을 분석하여 **정성적 취향 프로파일**을 생성한다. 통계/키워드 나열이 아닌, 서술형 문장으로 사용자의 감상 패턴을 포착.

### 입력
```json
{
  "reviews": [
    {
      "content_title": "string",
      "category": "string",
      "review_text": "string",
      "created_at": "string"
    }
  ],
  "previous_profile": "string | null",
  "language": "ko | en"
}
```

### 프롬프트 구조
```
[시스템]
너는 문화 취향 분석가다. 사용자가 작성한 평론들을 읽고, 그 사람의 감상 패턴과 취향을 정성적으로 분석하라.

## 분석 원칙

1. 서술형 문장: "· 해체된 구조와 서사를 통해 표현의 새로운 가능성을 탐색합니다."와 같은 형태. 키워드 태그나 수치 나열 금지.
2. 근거 기반: 실제 평론에서 드러난 패턴만 언급. 추측하지 않는다.
3. 크로스 카테고리 통찰: 영화와 음악에서 공통적으로 드러나는 성향 등을 연결.
4. 구체적 표현: "다양한 장르를 좋아합니다" 같은 모호한 문장 금지. 어떤 측면에서 어떤 경향이 있는지 구체적으로.
5. 변화 감지: previous_profile이 있으면 이전 분석과 비교하여 변화된 부분을 반영.

## 출력 구조

- profile_sentences: 5~8개의 불릿 문장 (각 30자 내외)
- recommendation_hook: 취향 기반 추천 유도 문구 1개

{language}로 작성하라.

[사용자]
평론 목록: {reviews}
이전 분석 결과: {previous_profile}
```

### 응답 포맷
```json
{
  "profile_sentences": [
    "해체된 구조와 서사를 통해 표현의 새로운 가능성을 탐색합니다.",
    "아이러니와 충돌을 통해 메시지를 전달하는 작품을 선호합니다.",
    "시각적 아름다움보다 질감과 분위기의 일관성에 민감합니다."
  ],
  "recommendation_hook": "경계를 허무는 실험적인 다큐멘터리 영화를 좋아하실 것 같아요. 추천해드릴까요?"
}
```

## 5. 콘텐츠 추천 — `recommend-content`

### 목적
취향 분석 결과 + 사용자 프롬프트를 기반으로 크로스 카테고리 콘텐츠를 추천한다.

### 입력
```json
{
  "taste_profile": ["string"],
  "user_prompt": "string",
  "review_history": [
    {
      "content_title": "string",
      "category": "string"
    }
  ],
  "language": "ko | en"
}
```

### 프롬프트 구조
```
[시스템]
너는 문화 콘텐츠 큐레이터다. 사용자의 취향 프로파일과 요청을 바탕으로 콘텐츠를 추천하라.

## 추천 원칙

1. 크로스 카테고리: 사용자가 특정 카테고리를 요청하지 않았다면, 카테고리 경계를 넘는 추천을 포함하라 (예: 영화 취향 기반 → 책 추천).
2. 추천 이유 필수: 사용자의 취향 프로파일과 어떻게 연결되는지 1~2문장으로 설명.
3. 다양성: 같은 작가/감독의 작품을 2개 이상 추천하지 않는다.
4. 중복 제거: review_history에 있는 작품은 추천하지 않는다.
5. 실존 작품: 실제 존재하는 작품만 추천. 확신할 수 없으면 추천하지 않는다.

## 추천 수
- 3~5개

{language}로 작성하라.

[사용자]
취향 프로파일: {taste_profile}
사용자 요청: {user_prompt}
이미 감상한 작품: {review_history}
```

### 응답 포맷
```json
{
  "recommendations": [
    {
      "title": "세계의 끝과 하드보일드 원더랜드",
      "category": "book",
      "creator": "무라카미 하루키",
      "year": 1985,
      "reason": "해체된 이중 서사 구조가 당신이 기생충에서 높이 평가했던 구조적 긴장감과 맞닿아 있습니다.",
      "reason_short": "이중 서사의 구조적 긴장감"
    }
  ]
}
```

### reason vs reason_short
- `reason`: 카드 확장(accordion) 시 표시되는 전문
- `reason_short`: 카드 기본 상태에서 표시되는 1줄 요약

## 공통 규칙

### 에러 응답 포맷
모든 Edge Function은 LLM 응답이 예상 포맷과 다를 경우 재시도(최대 1회) 후에도 실패하면 다음을 반환:
```json
{
  "error": "generation_failed",
  "message": "응답을 생성하지 못했습니다. 다시 시도해주세요."
}
```

### 토큰 관리
- 인터뷰 대화가 길어질 경우, conversation_history에서 오래된 Q&A를 요약하여 컨텍스트 윈도우를 관리
- 요약 기준: 10개 이상의 Q&A가 쌓이면, 가장 오래된 5개를 3문장 요약으로 압축

### 응답 언어
- 프롬프트의 시스템 메시지는 항상 한국어로 작성 (프롬프트 관리 일관성)
- LLM 응답 언어만 `{language}` 변수로 동적 지정
